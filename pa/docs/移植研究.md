# pa/ 移植研究——上游价格行为分析内核 → 自研模块(2026-10-06)

> 结论先行:上游核心能力 = 五大件(两阶段流水线、提示词组装与 KV 前缀链、五分类校验+宽松修复+反作弊、程序特征引擎、记录与增量基线),全部是纯 Python + 文本,与 GUI / 数据源 / IDE 网关完全解耦,**移植可行**。本库 `pa/` 骨架(12 个 docstring 桩)已就位,但其中 5 处集成点名称是 MT4 时代遗留,本文按 MT5 现状校准;并按"避免原名称与原说法"的要求给出**去名称化映射表与清洁室纪律**。

## 0. TL;DR

1. **范围**:上游 ~20 个内核文件构成全部核心能力;GUI(60+ 文件)、IDE 网关中继(qclaw/qoder/trae/cursor/workbuddy)、A 股数据源 5 套、飞书/PushPlus 通知全部丢弃。核心依赖只有 `openai` + `jsonschema`(本库 pyproject 需新增,现有依赖无冲突)。

3. **命名**:三张映射表(§2.3 模块/类、§2.4 JSON 契约与枚举、§2.5 编号约定与模板文件)+ 保留清单(§2.6 通用交易词汇)+ 静态命名卡口(§2.7,建议 `tests/test_pa_naming.py`)。
4. **工作量**:沿用《PA克隆方案.md》§5 的 4–6 周估计不变(阶段 0–5),集成点按 §3 校准后无需返工设计。

### 1.2 上游 LLM 层的可取事实

`ai/deepseek_client.py`(912 行)名字叫 DeepSeek,实为 **OpenAI SDK 通用流式封装**。可取的是两条**客观事实表**(对第三方网关 API 的参数要求,属事实而非表达,重验后可收录为数据):
- thinking 参数格式按网关不同(SenseNova `enabled/disabled`、B.AI 与 DeepSeek `adaptive+output_config.effort`、Anthropic 系 `budget_tokens`、MiniMax `reasoning_split` 等);
- max_tokens 上限按网关不同(8K ~ 393K)。
另外它确认了 `reasoning_content` 的保存/回放问题(部分网关多轮会丢思考流)。**丢弃**:IDE 网关中继全家桶(qclaw/qoder/trae/cursor/workbuddy,约 4000 行"白嫖 IDE 订阅"适配器)与两阶段里的网关 fallback 链。

### 1.3 丢弃清单

GUI 全部(`gui/` 60+ 文件 + 主题/动画)、`main.py`/`app_context.py`、`demo/`、`notify/`(飞书/PushPlus)、IDE 网关件(§1.2)、非 MT5 数据源 20+ 文件(akshare/eastmoney*/tushare/baostock/yfinance/tradingview*)、A 股件(涨跌停/复权/符号表)、PyQt 会话 token 台账(重写 10 行纯 Python)、事件总线/刷新循环(PyQt)、"校验问题文本逐字比对"的强耦合思路(本库宽松化:按节点 ID 校验,不按字面)。

### 1.4 依赖

## 4. 目标架构

### 4.1 宿主与跨进程设计(核心决策)

事实:引擎与面板**两进程**。pa 服务线程放**面板进程**:

- **数据**:闭合 K 直接读 L1(`data/database.get_candles`,`ohlcv`/`ohlcv_clean`;引擎持续刷新,DB 即最新)。分析硬语义=只用收盘棒,forming bar 不需要;**哨兵**=轮询该周期最新收盘时间戳变化(替代上游的收盘秒表;周末停盘 DB 无新行,天然安全)。
- **推送与注入**:WS 流式推送同进程直连 wshub;AI 聊天上下文注入同进程(`dashboard/ai_api.py`)。
- **跨进程结论文件**:`data/pa/state.json`(原子写:tmp + `os.replace`)。面板进程写;引擎 `calc_gate_state` 读(G12 门控,`pa_gate.enabled` 默认 false,拦截必写 reason 落 signals 日志)。引擎进程零新增线程、零 LLM 依赖。
- 代价:面板关窗则分析停——advisory 功能可接受;引擎不受影响。
- 否决的备选:宿主=引擎进程(WS 推流与聊天注入都要跨进程 IPC,复杂度高)。

## 6. 风险与实测坑(上游实测经验,事实性)

1. **弱模型 schema 漂移**:增量轮照抄阶段一格式,输出契约+尾部提醒都拦不住 → 校验体系先行(阶段 2 提前);持续跟踪配强模型;保留"失败弹原始响应"调试路径。
2. **中转站网关**:`/v1/models` 常空、模型 ID 非标别名、套餐白名单 403 → 上线前 1-token 探活;参数剖面表按当时供应商重验后收录。
3. **metrics 类错误禁止自动重试**(模型会为凑 RR 改止损)→ NO_RETRY 清单保留该设计,前缀随新规则 ID 重写。
4. **LLM 成本**:两阶段全量 10–20 万 prompt tokens/轮,前缀链后增量轮省 60% → usage 并入面板统计口径。
5. **门控误杀**:G12 初期只做"flat/standby 禁开仓"级低风险规则,每次拦截写明 reason;观察 2 周再谈置信度门控。
6. **时间**:窗口一律用 B 序号(免疫服务器偏移);展示层过 `data/server_offset.json` 校准值;H4 桶对齐宿主口径(`timestamp % 14400` 类偏移桶)。
7. **上游 trace 逐字比对问题文本**的强耦合不照搬:本库模板问题文本自写,校验按节点 ID 与字段,不按字面匹配。
